# MEB CAN IDs — карта CAN-идентификаторов

Для проекта `vw-meb-canfd-simulator`. Заменяет таблицу из раздела 3.2
`ARCHITECTURE_PLAN.md`: та таблица (формат `0x18DAxxxx`) не подтверждена ни
одним источником ниже и не совпадает с реальной адресацией VAG.

## Как читать этот файл

Каждая строка помечена уровнем достоверности:

| Метка | Что значит |
|---|---|
| ✅ ЛОГ | ID реально встречается в записи трафика (CAN-логи ниже) |
| 📘 DBC | Есть в DBC-описании MEB (opendbc, MIT), на вашей машине не проверялось |
| 📋 CSV | Есть в таблице сообщества spot2000 (собрана на ID.3), без лицензии — для коммерческого продукта нужно разрешение автора |
| ❓ UNKNOWN | ID виден в логе, но расшифровки нет |

Ничего здесь не проверено на вашем ID.7. Это отправная точка для сравнения с
вашим собственным захватом (`meb_listen.py` / Wireshark), а не готовый
справочник.

## 1. Battery (батарея, BMS)

### Широковещательные сообщения (расшифровка по DBC)

| Сообщение | CAN ID | Биты | Длина | Сигналы (основные) | Статус |
|---|---|---|---|---|---|
| `BMS_04` | `0x5A2` | 11 | 8 | режим BMS, ошибки, обесточивание, ёмкость | 📘 DBC |
| `HVEM_02` | `0x5AC` | 11 | 8 | ток HV-потребителей, полезная энергия (Вт·ч) | 📘 DBC |
| `MEB_HVEM_02` | `0xF7` | 11 | 8 | (сигналы не описаны в DBC, только счётчик `CNT`) | ✅ ЛОГ (7419 кадров в записи DCDC-Hacking) |
| `HVK_01` | `0x503` | 11 | 8 | целевые режимы BMS/DCDC/компрессора (коорд. HV) | ✅ ЛОГ (737 кадров) |
| `Battery_Temperatures` | `0x16A954A6` | 29 | 8 | макс./мин. температура батареи | 📘 DBC |
| `Battery_Heating_Status` | `0x12DD54D2` | 29 | 8 | нагрев/охлаждение, запрошенная и факт. мощность нагрева | 📘 DBC |
| `MEB_HVEM_01` | `0xBE` | 11 | 48 (мультикадр) | обороты и мощность электромотора | 📘 DBC |

### UDS-запросы (сервис 0x22, чтение)

| Группа параметров | Request ID | Response ID | Источник |
|---|---|---|---|
| Battery / Electrical / LSD / Technical (SOC, напряжение, ток, темп. ячеек и т.д., 142 параметра) | `0x17FC007B` | `0x17FE007B` | 📋 CSV (spot2000) |
| Battery, многокадровые (VIN блока, серийный номер, суммарный заряд/разряд) | `0x17FC007B` | `0x17FE007B` | 📋 CSV (спот2000, мультикадр, не разобран `meb_poll.py`) |

## 2. Thermal / Climate (климат, термоконтур)

| Сообщение | CAN ID | Биты | Сигналы (основные) | Статус |
|---|---|---|---|---|
| `Klima_11` | `0x3B5` | 11 | статус A/C, обороты компрессора, предупреждения | 📘 DBC |
| `Klima_12` | `0x668` | 11 | подогрев сидений (кнопки), разрешение доп. нагревателя, запотевание | 📘 DBC |
| `Klima_Sensor_02` | `0x5E1` | 11 | наружная темп., статус клапана отопления, насоса, муфты компрессора | 📘 DBC |
| `Klima_Sensor_04` | `0x5E9` | 11 | давление хладагента, статус ионизатора | 📘 DBC |

### UDS-запросы

| Группа | Request ID | Response ID | Источник |
|---|---|---|---|
| climate / Technical (темп. в салоне, снаружи, CO₂, рециркуляция, положение педали) | `0x746` | `0x7B0` | 📋 CSV (4 параметра) |

Внимание: адресация климат-блока (`0x746`/`0x7B0`, 11 бит) отличается от
адресации батареи (`0x17FC007B`/`0x17FE007B`, 29 бит). Это разные схемы
адресации в одной и той же таблице spot2000 — видимо, климат-блок и BMS
используют разный формат CAN ID. Проверяйте оба варианта при захвате.

|---|---|---|---|---|

### UDS-запросы

| Группа | Request ID | Response ID | Источник |
|---|---|---|---|
| Electrical / DCDC (ток и напряжение DC-DC) | `0x17FC00B9` | `0x17FE00B9` | 📋 CSV |

Диагностический адрес DC-DC по SSP 747 (отдельное пространство адресов ODX/
DoIP, НЕ CAN ID): `8105`.

`working1.csv`. **Это стенд без автомобиля и без шлюза J533** — набор ID
отражает связку тестера и отдельного блока DC-DC, а не то, что видно на
OBD-разъёме собранной машины. Не считайте список ниже типичным для вашего ID.7.

| CAN ID | Биты | Кадров в логе | Комментарий |
|---|---|---|---|
| `0x2AE` | 11 | 1484 | ❓ не в DBC, возможно `DCDC_01` |
| `0x3F4` | 11 | 1484 | ❓ не в DBC |
| `0x20F` | 11 | 1459 | ❓ не в DBC |
| `0x271` | 11 | 731 | ❓ не в DBC |
| `0x5BB` | 11 | 146 | ❓ не в DBC |

## 5. Gateway / Terminal status (шлюз, состояние зажигания)

| Сообщение | CAN ID | Биты | Сигналы | Статус |
|---|---|---|---|---|
| `Klemmen_Status_01` | `0x3C0` | 11 | клеммы 15/50/S/X, **`BCM_Remotestart_Betrieb`** (флаг дистанционного запуска) | 📘 DBC |
| `Klemmen_Steuerung_01` | `0x58C` | 11 | управление клеммами, блокировка ELV, подавление сигнала зажигания | 📘 DBC |
| `Gateway_72` | `0x3DB` | 11 | агрегированные статусы BCM/замка/дворников (помечены `_alt`, то есть устаrevшие копии) | 📘 DBC |
| `Gateway_73` | `0x3DC` | 11 | передача, электростояночный тормоз, 2 нерасшифрованных поля | 📘 DBC |

`Klemmen_Status_01` стоит записать отдельно при тесте дистанционного запуска/
обогрева: в нём есть готовый флаг `BCM_Remotestart_Betrieb`.

## Как подтверждать записи в этом файле

1. Снимите трафик `meb_listen.py --dbc vw_meb_cantools.dbc --seconds 60`
   (сначала без `--fd`, затем с `--fd`).
2. Если ID из таблицы выше появился в вашем логе — поменяйте его статус на
   **✅ ЛОГ (ID.7)** и добавьте дату записи.
3. Если в логе есть ID, которого нет в этом файле, — добавьте строку со
   статусом ❓ UNKNOWN, вернитесь к ней после захвата при работе ODIS
   (см. план из `VNCI6154A_plan_issledovaniya.docx`, шаг 1).
4. Не переносите сюда ID из общих туториалов по UDS/ISO 15765-4 без проверки
   по реальному логу — именно так в план попала неверная таблица `0x18DAxxxx`.
